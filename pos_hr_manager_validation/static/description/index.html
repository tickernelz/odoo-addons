POS Manager Validation

Sensitive point of sale actions wait for a manager PIN, checked on the server, set per point of sale.

Per point of sale

In Point of Sale > Configuration > Settings, under Manager Validation, pick the validating managers and tick the actions they approve. Everything is off by default.

Needs Log in with Employees.

Twelve actions

  • Close the session, delete an order, remove a line
  • Validate a payment, discount, change a price, decrease a quantity
  • Cash in/out, create a product, fiscal position, pricelist, refund

A PIN that stays on the server

Each manager gets a separate POS Validation PIN of six to twelve digits in the HR Settings tab. It is stored hashed and never sent to the point of sale.

Five wrong PINs in fifteen minutes lock validation for that manager and that session. Every request is logged, without the PIN.

Also checked on the server

Closing a session, cash in/out, cancelling an order with lines, and refunds or payments from the backend need a validation. Synced orders with an unvalidated discount, pricelist, fiscal position, payment or refund are kept and marked for review.

Keypad, touch and physical keyboard all work; barcode scans are ignored while the PIN dialog is open.
